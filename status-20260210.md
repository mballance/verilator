## Recent Achievements (February 10, 2026)

### 1. Fixed Sample Function Argument Validation
**Problem:** Covergroup `sample()` method calls with incorrect argument counts were silently accepted.

**Example:**
```systemverilog
covergroup cg with function sample(int addr, bit is_read);
endgroup
cg cov1 = new();
cov1.sample(1);  // Should error: too few arguments
```

**Root Cause:** `V3Width::methodCallClass()` was prematurely setting `didWidth(true)` before calling `processFTaskRefArgs()`, causing the validation pass to be skipped.

**Fix:** Removed the premature `didWidth(true)` call, allowing proper argument validation to occur.

**Impact:**
-  `t_covergroup_with_sample_args_too_few_bad.v` now correctly fails
-  `t_covergroup_with_sample_args_too_many_bad.v` now correctly fails
- All 9 bad tests now work correctly (100% success rate)

**Files Modified:** `src/V3Width.cpp` (line ~4512)

### 2. Added Default Parameter Value Support
**Problem:** Sample functions with default parameters weren't preserving the defaults.

**Example:**
```systemverilog
covergroup cg with function sample(int addr, bit is_read = 1'b0);
endgroup
cg cov1 = new();
cov1.sample(5);  // Should use default for is_read
```

**Root Cause:** When creating function parameters from the grammar's parsed arguments, the code was cloning the dtype but not the default value expression (`valuep()`).

**Fix:** Added `valuep()` cloning when creating function parameters.

**Impact:**
-  `t_covergroup_with_sample_args_default.v` now passes

**Files Modified:** `src/V3ParseGrammar.h` (lines 137-157)

### 3. Fixed Sample Function Parameter Types
**Problem:** Sample function parameters were created with incorrect variable type (BLOCKTEMP instead of PORT).

**Root Cause:** Wrong VVarType enum value used during parameter creation.

**Fix:** Changed from `VVarType::BLOCKTEMP` to `VVarType::PORT` to match standard function parameter handling.

**Files Modified:** `src/V3ParseGrammar.h` (line ~142)

### 4. Enabled Negative Range Support
**Problem:** Bins with negative value ranges caused internal compiler error.

**Example:**
```systemverilog
covergroup cg;
    coverpoint value {
        bins negative = {[-100:-1]};  // Internal error
        bins positive = {[1:100]};
    }
endgroup
```

**Error Message:**
```
Internal Error: Unexpected 'NEGATE' expression under 'INSIDERANGE'
```

**Root Cause:** The parser creates `AstNegate(AstConst(100))` for `-100`, but `V3Width::visit(AstInsideRange*)` wasn't creating proper expression context for children. The `AstNegate` visitor requires a valid context (`m_vup`), which was null.

**Fix:** Changed `visit(AstInsideRange*)` to create proper expression context using `WidthVP{CONTEXT_DET, PRELIM}.p()`, matching the pattern used in `visit(AstInside*)`.

**Impact:**
-  `t_covergroup_negative_ranges.v` now passes
- Enables proper signed range support for coverage bins

**Files Modified:** `src/V3Width.cpp` (lines 3248-3253)

### Design Decisions

**Why AstCovergroup doesn't inherit from AstClass:**
- Verilator's AST enforces strict naming: non-final classes must use `AstNode*` prefix
- `AstClass` is final and cannot be subclassed
- Solution: `AstCovergroup` is parallel to `AstClass`, both inherit from `AstNodeModule`
- Tradeoff: Some code duplication, but maintains clean architecture

**Sample Function Implementation:**
- Creates two sets of variables:
  1. Member variables in covergroup (for visibility in coverpoints)
  2. Function parameters (PORT type with INPUT direction)
- Both sets cloned from grammar-parsed arguments
- Default values preserved via `valuep()` cloning
